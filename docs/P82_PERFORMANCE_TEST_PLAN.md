# P8.2 第二阶段性能测试口径

本机Windows 11 x64，既有Electron 45.2.1；模型固定为本地Mock，使用新SQLite及合成账号，不接触共享库。

优化前运行来自本轮起点源码备份的独立副本，各文件SHA-256与起点清单核对；不回滚当前工作树。前后使用同一测试流程和当前前端资源：三宠、两个有保存消息的聊天窗口、无草稿宠物列表主窗口。

每轮先暖机15秒，测主窗口可见30秒；关闭到托盘后等待75秒，再测30秒。保留逐进程CPU/工作集/私有提交内存与window→renderer PID映射。CPU为Electron进程树指标，不是全系统占用；汇总工作集可重复计算共享页。

主窗口含输入框、表单、弹窗或不在宠物列表时不释放。最早一轮停留在聊天首页，因此保留了输入框；该准备测试提前正常结束并完整保留，不计入30分钟通过结果。

最终稳定性运行至少30分钟真实墙钟时间，每10秒采样，每2分钟恢复主界面并关闭/重开两个本地聊天窗口；记录主界面是否确实重建，不用动作名称代替实际证据。测试窗口使用明确记录的showInactive仪器设置，避免长测持续抢占其他应用焦点；正式焦点与物理鼠标行为另由Windows原生E2E验证。

## 分析门槛

- 全部样本保持3个宠物、2个聊天窗口，原生窗口不超过6，登记发送者与存活窗口数一致；没有未注册窗口或身份失效。
- 实际运行不少于1,800,000ms；正常退出与两端口释放。
- 私有提交内存峰值不超过768MiB；安静且主界面已释放的样本平均CPU不超过2%。这只是本机开发构建失控保护，不是消费者资源承诺。
- 比较第5–10分钟与最后5分钟中主界面已释放的样本，末段私有内存均值增幅不超过64MiB；分组分析稳定窗口数量下的趋势，不能把临时重建峰值直接叫作泄漏，也不能只用最后一帧宣布无泄漏。
- 30分钟不足以证明永不泄漏；未覆盖低配置机器、休眠唤醒、实际多屏热插拔或24小时运行。

测试过程中可能并行执行本项目构建与离线回归，均不计入Electron进程树内存；长测说明混合开发负载下的稳定性，短基准用于前后对比，二者不混算。

初次仪器准备出现过一次未保存详细快照的窗口数量断言失败，不能确定当时是否存在短暂原生窗口；该结果保留且不计为通过。后续基准与长测保留详细异常快照，以区分持续重复窗口与瞬时状态。最终结论限于实际有证据覆盖的范围。

本轮追加独立原生离线实验，确认close()通常返回后约5–6ms才closed，测试beforeunload处理可将其推迟到105–108ms。因此驱动关闭聊天时改为等待closed事件，超时失败而不强制destroy；不能把这一机制证据倒推为旧失败的确定根因。测试工具修改不改变产品代码或安装包。30分钟测量的脚本版本与后续驱动验证在最终报告中分别注明。
