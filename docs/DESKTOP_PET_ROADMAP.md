# WeiBiYe 桌面宠物开发路线

更新日期：2026-11-02。目标是普通用户可下载安装、与多只 AI 宠物自然聊天的 Windows 产品。宠物作用域基础已通过隔离验收；P6新增Electron＋React三宠桌面开发预览，各项Windows实测以P6验收证据为准。公开发行仍未完成。

## 阶段0：收敛现有产品界面

保留聊天、记忆、账户和宠物入口；移除社区、帖子、求职记录及对应展示数据，修订导航和说明。保留历史 API、模型、迁移、报告和备份，待确认的模块不擅自删除。

验收重点：旧社区／求职入口不再出现，旧深链安全回退；认证、聊天、SSE、记忆及桌面／移动导航无回归；页面明确当前 Mock 和尚未实现的桌面能力。本轮实际结果由执行时的验收记录提供。

## 阶段1：宠物作用域与人格契约

本阶段契约和实现见[PET_SCOPE_CONTRACT](PET_SCOPE_CONTRACT.md)、[客户端调用准备](PET_DESKTOP_API.md)与[PET_SCOPE_VERIFICATION](PET_SCOPE_VERIFICATION.md)。实现使用8张新增隔离表，保留旧版聊天和记忆。共享库尚未升级0006。

- 所有私人查询和命令同时校验当前用户与目标宠物。用户 ID 或宠物 ID 都不能由前端隐藏按钮替代后端校验。
- 实现宠物创建、编辑、选择、隐藏与归档语义（物理删除另行设计）；宠物人格真正进入受控上下文，不只是展示一个 persona 字段。
- 设计独立的宠物记忆、授权、检索、来源、版本与隐私屏障；账户级跨宠物一键总撤销尚未实现，不能宣称旧版账户开关会关闭所有宠物授权。
- 旧账户级记忆保持原状，不向宠物开放、不擅自复制；归属变更API尚未实现，未来需另行设计并由用户明确选择。
- 会话列表、候选预览、SSE 重放、缓存和迟到响应均带作用域，切换宠物后不串会话或记忆；宠物最近话题另行设计，当前不读取旧版账户摘要。
- 人格、记忆数据和用户输入的信任层次保持分明；检索出的记忆不提升为任意系统指令。

验收门槛：同用户宠物A／B、不同用户及未登录三类隔离矩阵通过；实际 Provider 输入能证明正确人格和仅授权记忆；删除、撤销、取消、重放及并发切换不越界。未知数据库版本保护继续保留。

## 阶段2：Windows 宿主与单宠物窗口

P6已完成六仓库代码研究，选择Electron＋React以复用认证、SSE及记忆界面；没有预设PySide最佳，也不声称Electron最省资源。见[p6选型](p6/TECHNOLOGY_DECISION.md)与[Windows本地启动](P6_WINDOWS_START.md)。依赖仅安装于本Worktree，不安装全局软件。

主界面继续负责聊天、记忆和账户；原生宿主负责桌面窗口、托盘及受限系统交互。定义最小 IPC 契约和调用方校验，只允许列举的宠物操作，不接受模型输出的任意脚本、命令、文件路径或窗口控制指令。

同时确定可信桌面来源、Cookie 会话与续期方式，保留 CSRF、CORS 白名单及服务端归属检查；不能为接入桌面窗口直接放宽来源或关闭认证保护。

验收门槛：一只宠物可放到桌面、拖动、点击、互动和收回；窗口透明度、焦点、鼠标穿透、键盘操作、托盘、显示器切换和缩放可用；退出应用能回收窗口和运行任务。网页示例不能替代真实 Windows 验收。

## 阶段3：多宠物同时运行

P6开发预览限制同时三只、集中运动调度、主显示器工作区和内存内坐标；透明窗口、拖动、菜单、托盘和按pet打开聊天已实现。完整多显示器、睡眠唤醒、位置持久化、Win10与低配置长时间压力尚未验收。Live2D只预留能力槽，不含SDK或模型。

- 每只宠物有独立窗口状态、人格、聊天上下文和授权记忆作用域。
- 定义窗口生命周期、位置恢复、遮挡与交互规则，支持单只收回和全部收回。
- 设置账户与宠物两层并发及资源预算，限制动画刷新、后台推理和流式连接。
- 睡眠唤醒、断网、崩溃恢复与应用退出时不重复生成、不丢失已持久化消息。
- 不以喂食、金币、等级、任务打卡或充值压力替代自然陪伴体验。

验收门槛：多窗口压力、低资源设备、多屏／DPI、进程退出和宠物切换的隐私测试通过，并记录可接受的资源预算。

## 阶段4：GPT、DeepSeek 等模型提供商

保留可替换 Provider 结构和 Mock 测试路径。先明确托管服务与用户自带密钥的产品模式，再实现消费者设置与适配；当前不代表已有 DeepSeek 连接能力。

- 用户明确选择并启用提供商后才允许真实调用；说明网络发送、成本及错误状态。
- 服务端托管密钥不进入客户端资源包；桌面自带密钥方案需要操作系统安全存储和受限 IPC，不能放在 localStorage 或聊天日志。
- 验证各提供商的流协议、取消、超时、幂等重试、上下文预算、隐私撤销和记忆输入屏障。
- 提供商切换不能改变用户／宠物隔离，也不能静默把失败请求发送给另一家模型。
- 额度不足不删除记忆，不制造 AI 情感依赖或诱导充值。

验收门槛：先通过 Spy／Mock 和隔离测试；真实付费模型联调需另行明确授权、凭据与成本范围。本轮不进行真实调用。

## 阶段5：消费者可安装版本

完成 Windows 安装、签名、更新、卸载、崩溃恢复、无障碍与隐私说明。默认按普通用户权限运行，明确自启动、网络和数据保存选择。

普通用户不应先安装 Python、Node、Docker、PostgreSQL 或 Redis。现有开发基础设施不作为消费者安装步骤；桌面客户端、托管 API 与本地数据存储的分工需先确认，再设计安装与离线行为，不假定已有离线能力。

更新策略需保持数据库能力兼容；应用二进制回退不等于允许数据库 downgrade。卸载和账户注销应向用户说明数据保留与删除范围，不自动覆盖、清空或擦除备份。

验收门槛：在干净 Windows 环境安装和升级，在标准用户权限下使用聊天与多宠物功能；无秘密进入日志或安装包，断网和重启后可恢复，卸载无遗留运行任务。没有经过这些步骤前，不宣称可公开发布。

## 待确认的横向决策

| 决策 | 确认前的边界 |
| --- | --- |
| Windows 宿主技术 | 不引入框架依赖，不预设特定方案已经通过多窗口验收 |
| 客户端与服务端分工 | 确认本地／云端数据、离线边界和运行时打包，不要求消费者自行部署开发环境 |
| 钱包、订阅和模型额度 | 保留旧结构，不开发金币、充值或支付通道 |
| 后台、社区审核和公开 Mock 端点 | 保留兼容与安全能力，不继续扩张原业务；退役需独立计划 |
| 旧记忆分类、词法及 Prompt | 保留契约和历史内容，不凭新产品文案改写用户数据 |
| 旧数据的宠物归属 | 用户明确选择后再迁移，不默认共享或自动授权 |
| 旧版未归属新建入口 | 当前保留旧v1读写兼容；桌面端仅调用显式pet路径。停止旧版新建或改为只读需单独确认契约与导航切换 |

每阶段进入开发前应冻结对应接口与文件修改边界，使用独立分支／Worktree、隔离数据库和可复现的测试记录。没有通用 Agent 平台、多智能体市场、社区或求职业务的后续开发阶段。
