# Windows 分数缩放下的桌宠窗口尺寸保护

本轮环境：Windows 11，Electron 45.2.1，显示缩放 125%。仅针对本项目透明宠物窗口；没有修改操作系统缩放设置、其他应用、共享数据库或其他 Worktree。

## 实际问题与实现

原实现使用 `setPosition()` 移动窗口。在真实 Windows 验收中，窗口的逻辑尺寸出现从 188 逐步变为 191、194、215 等累积增长，导致实际窗口、角色命中区域和预期坐标不再一致。这不是通过修改测试断言就能忽略的问题。

当前宿主独立实现以下保护：

1. 透明、无边框宠物设置 `thickFrame: false`，避免不需要的 Windows 非客户区边框。
2. 所有自主运动和拖拽通过 `setBounds({x, y, width: 188, height: 196})` 明确传入原始 DIP 尺寸，不读取当前窗口尺寸再写回，不再调用 `setPosition()`。
3. 分数缩放下，原生窗口尺寸读取仍可能向外取整一 DIP。空闲时仅容忍宽高各自偏离目标不超过一 DIP；超过范围仍纠正。该容差不传递到下一次移动请求，不允许尺寸逐次累加。
4. 按下宠物时立即暂停该宠物的本地运动，防止等待真实身份与归属检查期间角色移走；鉴权成功后才允许拖动。鉴权等待期间最多保留最后一个有限坐标，失败或 Cookie 变更时撤销。

## 证据范围

- 单元回归模拟原生位置更新每次增加尺寸，检查十秒逻辑时间的 200 次宿主 tick 与多次拖拽均显式保持原始尺寸请求。
- 单元回归检查固定一 DIP 的返回取整不会引发每秒二十次的无效空闲重设；三 DIP 的异常仍触发纠正。
- 真实 Windows 诊断已观察到原始尺寸恢复为物理 235×245 对应逻辑 188×196；进一步十一秒移动采样出现逻辑宽 188/189、高 196/197 的有限变化，没有原来的持续增长。
- 上述诊断不替代最终验收。最终报告应保留原始采样，并要求每项偏差不超过一 DIP、整个采样最大值与最小值之差不超过一 DIP，同时确有实际移动；仍须以可信操作系统鼠标事件验证拖拽与移动中点击。
- 之前一次无鼠标事件的失败还涉及验收主窗口的置顶遮挡；调整验收窗口焦点后收到可信拖拽事件。不能把所有输入失败都归因于 DPI，也不能用合成 DOM 点击替代操作系统输入。

## 官方资料及不确定性

[Electron screen 文档](https://www.electronjs.org/docs/latest/api/screen) 明确 `getCursorScreenPoint()` 返回 DIP 点；本轮可信鼠标记录也显示物理坐标与浏览器屏幕坐标按 125% 换算。不要再对已经是 DIP 的值进行第二次缩放。

[Electron 窗口 API](https://www.electronjs.org/docs/latest/api/browser-window) 提供显式 `setBounds` 和独立的客户区接口。[官方仓库问题 51679](https://github.com/electron/electron/issues/51679) 的维护者说明，精确管理无边框几何时可使用 `thickFrame: false`。

[官方仓库 PR 55429](https://github.com/electron/electron/pull/55429) 描述 Windows 分数缩放的 DIP 与物理像素向外取整，以及读取再写回尺寸的增长。核查时该 PR 仍为 Draft；它仅提供上游原因线索，不能宣称修复已合并、当前运行时已包含修复，或已经升级了 Electron。本项目采用上述自身保护，不依赖该草案代码，也未复制第三方实现。

本轮只在当前 Windows 11 主显示器实测。没有完成 Windows 10、多显示器混合 DPI 或所有缩放比例的兼容性验收，相关范围应留待后续发布测试。
