## 2. 未来执行环境与隔离

- 所有数据库写入测试使用事先确认不存在的新库，例如 `weibiye_p4_test_<run_uuid>`，绝不能复用 `weibiye`。连接必须确认127.0.0.1:25433、独立库名、cluster标识、当前版本及测试标记；库名之外还须实际 current_database 校验。
- 只使用现有本项目基础设施，不重启/重建任何容器。Redis测试使用明确 `p4:test:<run_uuid>:` 前缀或独立已确认逻辑DB，禁止 FLUSHDB/FLUSHALL 及扫描删除其他命名空间。
- 建议测试 API/frontend 端口 38304/35304，仅127.0.0.1；执行前检查占用，冲突则暂停，不杀占用进程。前后端都指向同一个明确测试配置，真实模型强制关闭。
- 至少两账号 A/B，使用 `p4-<run>-a/b@example.com`，合成事实不同但标题/IK可相同；浏览器用两个隔离 context，并增加同一 context 内切号测试。
- 使用 Mock、CapturingMock/SpyProvider 与本地 Mock 邮件，不发真实邮件。临时 Provider 只捕获当前测试输入进行断言，不把完整 Prompt 作为提交产物。
- 测前/后快照开发库版本/结构/记录、容器ID/状态及各Worktree；服务只停止本次启动的PID。保留可识别测试库与证据，不以 drop/truncate 或全库清理收尾。其他旧项目自动变化须单独记录而非归咎/掩盖。

## 5. 取消、删除与并发回归

使用独立 PostgreSQL、多连接和 barrier/event 控制调度，不用 sleep 假定竞争发生，不只依靠 SQLite。每个事务失败路径检查回滚与唯一约束。

| ID | 可控制交错点 | 断言 |
| --- | --- | --- |
| R01 | 同IK同请求并发确认 | 一条Memory、一组来源、一个grant、一个命令结果 |
| R02 | 同IK不同内容 | 409，不覆盖任何已提交事实 |
| R03 | 编辑/删除后重放旧create/edit | 当前状态结果；不返回旧正文，不恢复资源 |
| R04 | 两窗口同时纠正 | 仅一个版本成功，另一个409，不能丢失更新 |
| R05 | preview后关闭/来源删除/切号 | 确认拒绝，签名回执不当权限凭证 |
| R06 | 检索后、Provider授权前撤销 | Provider没有收到旧记忆，任务合法取消 |
| R07 | 已授权发送、网络在途时删除 | 明确“不能召回”边界；之后无新delta/completed提交，唯一取消终态 |
| R08 | queued任务pinned IDs后纠正 | 旧epoch失效，不静默重检索生成替代回复 |
| R09 | delta已提交、下一flush前删除 | 后续无delta；现有partial保留并标取消，事件序号连续 |
| R10 | 完成与取消同时竞争 | 一个唯一终态，消息/任务/事件元数据一致 |
| R11 | 过期/来源失效后台尚未运行 | 懒检查仍推进屏障并拒绝旧快照 |
| R12 | 删除后旧来源原文/旧助手转述/多轮传播 | SpyProvider自动历史不含低于floor轮次；同时间戳、worker时钟偏差、legacy NULL也不绕过，floor永不回退 |
| R13 | 用户新输入主动重复旧事实 | 仅作为新当前输入，不误称系统从记忆恢复 |
| R14 | User/偏好/Session/Generation多线程命令 | 无反向锁序；有界超时/回滚，不提交半套证据 |
| R15 | Redis/DB失联、epoch复核失败 | 不使用旧缓存放行；隐私操作失败诚实提示，不假成功 |

另测新增/开启只推进epoch不推进floor，旧完整历史仍可重用；偏好版本只因全局设置修改递增。认证/限流Redis不可用应503，不能绕过撤销检查；仅通知publish失败时，已提交删除仍成功、其他端通过epoch和轮询失效。

还要验证旧SSE重放仍可展示历史partial，但不会调用Provider或重检索；删除记忆与删除聊天的语义不可混淆。

## 6. 检索与预算验收

建立版本化合成金标集：50个话题查询（20求职方向、10重要经历、10未完成事项、10无关负例），另10个交流偏好场景；每个正例列出最多5个确切相关memory ID、可允许的排序与已失效负例。A/B各含同名、相近、相反偏好的事实，分别测试候选为空、满200条、Unicode中文短语、同义词局限和完全无关输入。

提案门槛：正例返回集合精确率宏平均≥0.90、Recall@5宏平均≥0.85；精确率=`相关返回数/返回数`，正例空返回精确率记0，召回分母为该查询金标相关数。10个无关负例均应返回空。交流偏好作为明确启用的独立候选测试，不混入话题命中率虚增指标。跨用户、撤销/删除/过期/未授权命中率必须**0**，不能用平均相关性抵消权限失败。门槛需在开始实现前确认，实际失败如实记录。

预算测试至少覆盖：

1. S+U+H+M+O+G不超过C；M≤1024且≤15%边界、最多5条。
2. 中文、emoji、长否定句、混合语言；已验证计数器与Provider配置一致。
3. 当前输入/安全提示/输出预留优先；按完整轮次裁剪H，不拆用户与助手对。
4. 记忆按整条加入或跳过，不截断为相反含义；预算为0不注入且不删记忆。
5. 未知真实模型容量或tokenizer拒绝真实调用；Mock专用计数器不能被当作真实token证据。
6. CapturingMock直接检查最终输入、memory ID/version/source及计数，固定回复不作为“记住了”的证据。
7. 汇总仅为显示的确定性摘录，无来源外事实；用户编辑后不能沿用旧grant。

检索性能在说明硬件/数据规模的条件下记录p50/p95，不把尚未测量的毫秒值写成承诺；先限制扫描规模、检查索引和SQL次数，再决定是否需要其他索引技术。

## 7. SSE、浏览器与多端

- 保留P3所有SSE解析、去重、Last-Event-ID排他重放、410恢复、幂等与停止回归；记忆注入不增加重复用户消息或隐性第二次Provider调用。
- start/delta/completed/error/cancelled版本仍为1；新增cancelled.reason字符串需前端兼容，旧未知reason回退不崩溃；终态finish_reason/usage仍与快照一致。
- Playwright桌面与移动视口：默认关闭→开启→手动/消息预览→确认→列表/来源→纠正→撤销→重新确认→删除→导出，提示状态与真实API一致。
- 同账号双context和两个账号：切换、刷新、失焦/聚焦、30秒元数据轮询、断网恢复、旧epoch延迟响应、BroadcastChannel仅失效信号。
- 离线点击关闭/删除显示未确认，不伪造成功；恢复先同步，不能覆盖服务器撤销。不同账号不能使用同cursor或读取导出。
- 保留“今天还顺利吗？”“不管发生了什么，都可以和我聊聊。”“愿意和我聊聊吗？”、历史会话与最近话题卡；已有会话不重复欢迎语。
- Windows/App/桌面宠物本轮仅协议设计，网页多context不能被报告成这些真实客户端已验收。
