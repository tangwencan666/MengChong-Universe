# P4 长期记忆隐私与安全设计

状态：**待实现、待验收的设计要求**，`p4-memory/1.0-draft`，2026-11-01（Asia/Shanghai）。不构成生产安全、医疗或法律合规认证。本轮只写文档，不修改现有认证或数据库。

## 1. 信任边界与默认值

| 边界 | 规则 |
| --- | --- |
| 浏览器/未来客户端 → API | 现有 HttpOnly Cookie 会话；写请求 CSRF+Origin+Sec-Fetch-Site；生产 HTTPS/Secure |
| API → PostgreSQL | owner 来源只取 Principal，所有查询/关联包含 owner，管理员不能读取私人记忆 |
| PostgreSQL → Redis/客户端 | Redis 仅限流/失效信号，不作为授权依据、不放正文；客户端默认不落盘 |
| Memory → LangGraph/Provider | 每次权限/有效期/来源复核，低信任数据而非系统指令；不进入公共 demo/community/moderation Prompt |
| Provider/SSE → 用户 | 同用户任务、lease+epoch fence；不以 SSE 广播授权记录或记忆全文 |

全局长期记忆默认关闭，最近话题授权完全独立。不存在 MemoryPreferences 行不创建授权，也不为了 GET 写一条默认启用记录。旧 `memories.consent_granted_at` 无法证明已接受 P4 披露，迁移后必须隔离为 legacy_unconfirmed。

## 2. 威胁与防护矩阵

| 威胁 | 设计防护 | 必要证据 |
| --- | --- | --- |
| 跨用户 IDOR、伪造来源 | owner SQL 过滤、复合 FK、父会话/消息同时校验、统一404 | A/B 同内容不同ID、混合来源及管理员回归 |
| CSRF/跨站保存或删除 | 复用现有 principal_for/check_csrf；所有 POST 含只读计算也校验 | 缺/错 token、非白名单Origin、cross-site 均拒绝 |
| 自动挖掘/宽泛同意 | 全局开关+逐条确认；仅显式选择来源；预览不保存 | 总开关打开后零事实写入、未确认无 Memory/来源/授权事件 |
| 提示词注入、恶意偏好 | 结构化资料区、长度/类别限制、敏感筛查、固定安全指令、无工具提权 | “忽略权限”“发送其他用户记忆”等金标不能改变授权 |
| 缓存/幂等复活 | owner/auth scope/epoch；无正文幂等缓存；墓碑、当前状态重放 | 旧创建 key、晚到响应、重连、切号后不能还原正文 |
| 删除后派生历史泄漏 | 账户上下文时间屏障、旧epoch任务取消、Provider/flush前复核 | 原来源、旧助手转述、多轮传播均不再被自动注入 |
| 模型/日志/导出外泄 | 仅 Mock、tracing关、日志白名单、导出 owner/no-store/有界 | SpyProvider输入及日志扫描，无 Cookie/令牌/正文 |
| 资源耗尽 | 内容/条目/来源/候选/导出上限、限流、短事务 | 并发超限与Redis/DB故障不绕过授权 |

## 3. 授权证据与撤销语义

授权记录只包含 owner、memory ID/版本、操作、披露版本、认证 session 关联、客户端类型和服务端时间；不复制正文、IP画像或自由文本“同意理由”。客户端 declared client_type 仅作展示/诊断，不授予信任；session 身份来自服务端。

保存必须同时满足：全局开启、当前偏好版本、用户逐条确认、来源真实且归属一致、内容符合安全策略、事务提交。任何模型输出、聊天中的一句“记住”、最近话题授权、预览请求或余额都不能代替确认。

全局关闭立即停止使用并撤销全部 active 条目；正文可供本人管理，开关重新打开不复活。单条 revoke 同理；重新确认产生新授权版本。用户拒绝新披露版本时仍可查看、撤销、删除、导出，不能用强制同意阻止退出。

审计与同步只含 ID/版本/动作，拒绝的预览或敏感输入不作为审计正文保留。有效 grant 事件不得在仍被引用时清理；同步窗口90天、有效授权生命周期+终止365天等保留期是待落地提案，不能把此文档当作已运行清理任务。

## 4. 删除、纠正与生成竞态

删除的服务端线性化点是数据库事务提交：条目正文/标题/摘要清空，grant 失效，无正文墓碑/事件与幂等映射保留；epoch 递增、上下文屏障推进、旧任务取消。纠正以当前版本替换正文，不留旧明文版本；来源索引不再返回被删内容。同一Memory ID来源不可改写；重新确认复核原来源，缺精确证据的legacy须另建明确授权的新ID，避免旧生成引用的来源被篡改。

锁顺序遵守 User→MemoryPreferences→Session→Generation→Message→Memory，不在锁内访问网络。Provider 前的短事务确认及记录引用是授权发送点；随后网络属于在途操作。撤销先提交，新任务不得获得授权；授权发送先完成的输入可能已在途，无法保证撤销后网络绝无数据到达。

每次 delta/finish 保存均在原 lease fence 之外再校验 epoch、条目版本/资格。失效后只允许合法取消终态，不允许新 delta 或 completed。检测至客户端关闭前的已发送字节不能回收，不能把“取消请求已接受”宣称为所有外部副本被删除。

仅停止检索不够：旧助手回复可能转述记忆。首版对删除/纠正/撤销/到期/来源失效设置账户级 `context_epoch_floor=递增后的privacy_epoch`；未来自动历史要求 `COALESCE(generation.memory_epoch,0)>=floor`，旧 queued pinned IDs 同样失效。context_not_before仅作显示，不能用时间条件OR绕过逻辑屏障。新增/开启不推进floor，避免无故丢历史。所有旧epoch活跃任务停止，重新请求由用户主动发起，不静默生成替代回复。

用户仍可以阅读历史聊天和原 SSE journal；这是聊天留存，不是授权将其再次注入模型。记忆删除不是会话删除。若用户要抹除历史会话，需另行使用会话删除并了解当前逻辑删除边界；本轮不宣称已经实现全账户物理擦除。

## 5. 到期、来源删除及派生数据

资格过滤必须在 SQL/服务端生效，不依赖前端隐藏或后台扫描及时。到期、来源会话墓碑、旧 grant/version 均阻止注入。新任务/Provider/提交前懒处理失效，后台扫过期只能改善状态展示，不能作为权限门。

来源删除默认使派生记忆不可用，并推进屏障。不能转用旧摘要、Redis缓存、搜索索引、旧导出或生成引用复原正文。用户要脱离来源保留事实，必须主动新建手动条目并确认；系统不得静默“转存”。

第一版不使用向量或持久检索缓存；未来增加 embedding 时，向量、分词索引、摘要、导出对象都属于受同一删除和 owner约束的派生数据，不能以“不是原文”为由豁免。

## 6. 敏感信息与心理健康安全

禁止自动存储密码、密钥、验证码、金融/证件号码、精确住址、第三方隐私、诊断/危机心理画像。首版对于这些类别即使手动请求也保守拒绝，避免“全局同意”覆盖高风险内容。筛查既在预览前也在确认/纠正前执行，错误不回显值；混合正常与敏感事实不能未经确认自动拆分后保存。

不承诺确定性检测能捕获所有敏感信息。必须有中文/英文、混淆、分隔符、编码和上下文金标；无法可靠识别时不自动提取，而不是调用付费模型猜测。向真实模型发送资料处理本身也需要未来单独的提供商/数据处理授权。

高风险心理表达不变成长期标签。未来安全门应提供有限而自然的支持，鼓励现实中的可信支持/专业帮助，不作诊断、不自称人类或治疗师、不夸大保密/监护能力。危机内容不触发记忆候选、营销或充值。若未来提供具体当地热线，须届时核实适用地区与有效号码；本设计不列未经验证号码。

Token 用完不删除记忆，不限制隐私管理；安全回应不与余额/充值绑定。不得以“失去陪伴”“忘记你”等措辞制造依赖。安全门尚未实现前，Mock 或 Prompt 不能被当成已完成危机干预。

## 7. 多端、认证与缓存

不修改现有 auth Cookie/CSRF/RBAC。Owner管理只依赖当前已认证用户，不新增 X-User-ID、调试账号或客户端传 user_id。Windows/App/宠物不获得私人读取后台特权；新客户端 Origin 或原生认证方案需要单独评审，不能直接把 CORS 改为 `*`。

缓存键至少为 owner+auth scope+privacy epoch+资源版本。切号/退出取消所有记忆请求、清 Query 和临时输入；旧 epoch Promise 完成后不得回写。BroadcastChannel/Redis通知只传失效动作，不传播正文；不同账号即使 cursor/IK相同也完全隔离。

默认不使用 localStorage/IndexedDB/离线磁盘缓存记忆或长效认证 token。离线设备不能写授权，更不能本地显示“服务器已删除”；恢复网络先读取当前偏好与变化，不把旧本地数据上传覆盖撤销状态。前台轮询可延迟界面同步，但服务端安全检查不能延迟。

## 8. 导出、备份与日志

导出是本人当前非删除数据的受限只读快照，仍校验认证/CSRF，关闭记忆不剥夺导出权。无公开URL、无长期导出文件；下载后客户端持有副本不可召回。已开始返回的导出与网络在途响应存在同样边界。

备份不等于立即可物理删除的主库。拟议最长30天备份保留、隔离访问；恢复后必须应用备份之后的删除/撤销清单、重建无缓存授权状态并验证后才开放服务。跨备份持久删除清单的实现与恢复演练是公开测试前的必要条件，本轮没有建设；现有 P3 手工备份也不能被本设计自动清除。

只记录 request_id、owner内部ID、操作、资源ID、状态、耗时、计数器版本与预算数字。禁止 content、summary、query、完整来源、模型输入/输出、Cookie、CSRF、邮件token、密钥、原始数据库/SDK错误。服务端 HMAC 指纹不当作匿名化；密钥版本/轮换和历史幂等验证需测试，密钥只由未来安全配置注入。

默认禁用外部 LangSmith/遥测，不因 LangGraph 新节点改变此边界。测试只用合成数据/SpyProvider；浏览器trace、截图及导出也可能含隐私，产物不提交且应限制保留。

## 9. 故障与降级

PostgreSQL 无法确认授权时不得取用记忆。只有记忆专属检索能力故障、P3存储/lease/SSE仍健康、Provider尚未开始且未纳入记忆快照时，才可记录“跳过记忆”继续普通聊天。共享PostgreSQL不可用仍按P3失败/取消/503，绝不能改为无持久化回复；已有记忆输入且无法复核时取消原任务，不用旧缓存继续。数据库无法提交删除时必须报告失败/未确认，不能在 UI 显示删除成功。

Redis故障不能变成授权放行。当前认证本身依赖Redis撤销检查；认证或限流依赖失败时包括撤销/删除在内仍返回503，UI显示未确认并停止本设备继续使用，不能假装已提交，也不新增本地认证/限流旁路。只有事务提交后的失效通知是best-effort，发送失败不改变已提交结果；服务端epoch始终为安全依据，设备随后轮询恢复显示。未来如需提高隐私操作故障可用性，必须另审认证一致性方案，不能在P4中悄悄跳过会话撤销检查。

## 10. 参考与实施门槛

现有 CSRF 组合校验沿用不变；其多层防御原则可参考 [OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。记忆中的恶意指令、间接注入和数据外泄威胁参考 [OWASP LLM Prompt Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)；结构化分隔仍需实际权限、输出约束与安全测试，不能视为万能防护。

未通过跨用户隔离、隐私竞态、旧路由/旧幂等复活、备份恢复防复活及明确数据保留说明之前，不得宣称具备生产级长期记忆。真实模型、支付和公开部署始终另行授权。
