# 萌宠溜达未来30天：先验证用户价值

制定日期：2026-11-04。范围依据 `PROJECT_FULL_AUDIT.md` 与 `PRODUCT_BUSINESS_REVIEW.md`。这是后续计划，**本轮没有执行开发、安装、真实QQ、付费模型、数据库写入、部署、发布或Git提交**。

## 1. 30天目标与边界

不要把目标设为补齐所有功能。目标是作出一个有证据的决定：**优先做QQ陪伴、优先做Windows桌宠，还是暂停新增投入。**

保留现有八角色和桌面体验；冻结新增角色、永久帮派、更多动画、完整向量RAG、后台模型互聊和支付。只修会阻断首次/再次使用、数据安全和退出的缺陷。先5人观察，条件满足再到约10人，不直接做50–100人运营。

以下涉及真实连接、费用、外部服务器和分发的任务均需以后单独明确授权；本轮只记录前置条件。官方审批等待时间不可保证，不以技术绕过替代审批。

## 3. 第1周：把可交付边界讲清并证明

### 第1–3天：代码与证据基线

- 按已提交、历史未提交、本轮新成果分类；保全现有191条路径和证据。对宠物13文件、beta额度8文件、0006及前端前置逐项确认归属，不用reset/clean，也不整体add全部文件。
- 由成果所有者决定如何形成完整本地提交集合；本审计未授权代为整理提交。隔离目录检出候选，明确素材生成、锁文件和配置文档，避免隐式依赖开发者私人路径。
- 在新测试目标执行完整离线回归，分别记录pass/fail/skip与需要PG/Redis的条件，不把历史540项改称全量。必要迁移只用新隔离数据库，绑定集群/run_id/专属标识。
- 保留一份可追踪构建清单：提交集合、WIP是否存在、依赖锁、资源哈希、安装包版本与结果。以干净重建结果作为后续分发门槛。

**退出条件**：不能从完整候选独立构建/启动，或有归属冲突，停止受影响提交/分发；继续做访谈和许可核查，不覆盖他人文件。

### 第2–5天：渠道与权利

- QQ：用户在官方控制台人工确认机器人主体、C2C权限、内部体验名单/当前服务范围、是否可用WebSocket；保留不含凭证的确认记录。核查外部平台注册/绑定作为前置、统一托管及将来收费的具体方案是否允许；不将“官方支持WebSocket”当成商业许可。
- 素材：为拟分发的每种形象列原创/已授权/仅本地验证。没有授权的素材不随包外发；若用自有原创占位制作验证构建，应单独批准，不改用户当前所选资源和历史证据。
- 选择本月用户验证渠道：许可/操作简单者优先。QQ许可未清楚时，做本机演示/访谈，不公开服务；桌面不能独立使用时，先记录安装/后端缺口，不假装测试者会自行配环境。

第1周产出：完整可复现基线或阻塞清单、素材权利表、QQ许可问题表、10人候选访谈名单（不采集密码/Key）、单渠道测试说明。此处不要求招募者已经付费或对外公开。

## 4. 第2周：完成一条最小真实使用闭环

### QQ分支：仅在明确授权后

1. 按现有P8.7.2报告的受限沙箱流程，使用一个已批准测试身份；凭证只在操作者本机进程环境，不写报告/截图/命令参数，不让普通用户填DeepSeek Key。
2. 第一轮只用Mock，最多一条新聊天；绑定控制回复另计，遵守现有总外发限制。验证真实READY、事件身份、绑定、回复回执、撤销和退出。失败不自动起新一轮，不扩大intents。
3. 对协议拒绝/账号权限/网络/TLS/重复投递分别给出证据。真实消息成功也不代表10人运行或后台持续服务成功。
4. 如果选择继续真AI，先接统一生产额度域与服务端授权会话、补生产内容审核。网页/QQ同一owner并发、价格上界、故障后的未知费用和发送不明必须离线验证。
5. 取得新的模型费用授权后才可做极小真实测试；本计划不预授权任何付费请求。账号夜间保护/额度不足时应停，不调机器时间或换账号绕过。

现有本地WS沙箱每次10分钟/一条聊天，是测试护栏，不是10人内测服务。要改为可持续内测必须有单独设计、容量/隐私验证及授权，不能删除护栏后直接给人用。

### 桌面分支：用户条件优先

1. 当前版本重新构建，先用独立appId/profile验证，避免覆盖用户工作版本和草稿；随后经明确同意验证正式身份。
2. 在干净标准Windows账号验证安装、启动、覆盖升级、正常卸载、用户数据保留说明。真实下载来源安全提示另测，不绕过系统提示，不承诺未签名包不告警。
3. 如果需要后端，先用批准的独立环境/HTTPS/真实邮件/备份和额度；不把本机共享数据库改为公网服务，不把AppSecret/模型Key打包。公开部署和费用仍需单独确认。
4. 最小体验只要求用户选一只喜欢的宠物、完成互动、退出/再次打开。五宠仍可用，不把复杂社交设置当首次任务。

**退出条件**：没有一条能由非开发者完成的使用路径，就不放大到10人。记录真实阻碍，允许当周以5个指导观察会话替代“发行成功”的虚假目标。

## 5. 记忆与稳定性只做影响验证的部分

### 真实记忆准备

- 当前真实模型注入关闭是实际安全边界，不是漏开一个开关。先补真实模型输入/输出预算和删除/撤销并发栅栏，不能把Mock字节计数当Token上界。
- 先验证一个实例、一条用户明确授权的记忆是否能准确、安全影响候选；同账号同种另一实例/另一账号不可见；撤销/删除后后续上下文不再引用；没有事件时不能编造共同经历。
- 社会共同事件若要入模，先建立后端可核验的可信事件源和参与者权限，不直接信任renderer提交正文。未完成前继续明确标注本地小记。
- 不要求本月加向量库。检索相关性、真实性、许可和删除正确性比“用了RAG”的名词重要。

### Windows耐久专项

- 固定单宠/三宠/五宠与五同种，分别测聊天开关、召唤/收回、隐藏、正常退出；每组明确窗口数和进程身份。
- 优先无调试器2小时隐藏/恢复，再按条件做更长观察；对比每角色私有提交和暖机后增长，不把共享工作集求和当独占RAM。
- P8.6参考：五同种30分钟CPU0.630%、工作集峰1332.86MiB、私有峰612.07MiB、私有均值+44.84MiB。新结果需同口径；不沿用更早0.10%短测宣称当前空闲性能。
- 复查`0xC000041D`，保留异常退出和复现条件，不靠强制destroy或忽略非零退出通过。
- 当前只有单物理屏125%DPI；其他真实DPI、多屏插拔、系统休眠和低配机器须分别标实测/未测。用户参与期间不要抢全局输入，桌面自动测试另约安静时段。

仅做定位和必要修复，不因单次阈值外观好看无限微调。若资源严重影响普通电脑，优先默认一宠/减少闲置窗口或关闭后台活动，再决定是否值得架构改造；保留五宠功能及数据隔离。

## 6. 第3周：5人观察，满足条件再扩大到10人

招募经同意的成年熟人；说明是受控内测、模型/本地规则区别、费用/数据处理、退出/解绑/删除方式。不把测试机器人包装为真人或官方客服，不默认永久收QQ正文。

每人完成相同最小任务：

1. 未看开发文档，尝试开始使用并选择一只宠物。
2. 完成首次主动互动，辨认Mock/真实模型（以实际启用模式说明）。
3. 桌面用户尝试收回/恢复；QQ用户尝试绑定/撤销。允许失败并记录原因。
4. 正常退出；次日由用户自行决定是否回来，不用不断提醒制造假留存。
5. 访谈替代方案、真正喜欢/烦扰的点、是否想保留这只宠物；避免问“你觉得是不是挺好”。

桌面和QQ的结果分渠道，不混合分母。指导下完成与独立完成分开，开发者/自动化账号全部排除。5人发现严重阻碍应修根因，不靠继续邀请冲淡失败率。

扩至10人的条件：许可和数据权利清楚、预算/发送闸有效、无跨用户/跨宠泄露、用户能停止/解绑、没有阻断性退出问题、已有明确的使用说明和支持负责人。暂不做付费/充值；“愿意付费”的访谈只记意向。

## 7. 最小指标与告知

只收经同意的匿名化/假名化标识、渠道/版本、必要事件类别、时间和错误类别；不采集聊天正文、OpenID原文、密码、模型Key或AppSecret。哈希ID不等于绝对匿名。提供关闭和删除，先确认保留期限和负责人。

| 指标 | 定义 | 防止误算 |
| --- | --- | --- |
| 开始成功率 | 完成安装/绑定并进入体验的人数 ÷ 实际开始尝试人数 | 目前安装尝试采集未接通，首批可经同意人工记录；只数已装成功者没有分母 |
| 首次互动率 | 完成首次主动有效互动人数 ÷ 完成开始流程人数 | 固定欢迎、后台社交、Mock自动执行不算用户主动互动；Mock/真实分开 |
| D1 | 首次有效互动UTC日后第1个UTC日主动回来的合格用户 ÷ 已完整经过该日的首日队列 | 统一与现有日桶口径；不计自动计时/强制提醒/开发者账号，未到观察日不进分母 |
| D7 | 同上，第7日主动回来 | 明确是第7日，不偷换成七天内任意一天；报告人数和分母 |
| 价值反馈 | 用户主动提及愿意保留的具体能力、替代品与烦扰原因 | 口头满意不等于留存，口头报价不等于成交 |
| 成本/可靠性 | 实际Token与未知用量数、保守预算占用、真实供应商费用（若可靠）、失败/重复/排队/退出 | 例价不当实际账单；失败不当免费；未知投递不盲目重发 |

建议的**试验门槛而非行业标准**：约10名合格体验者中至少8人可独立开始，已到观察日的队列D1约40%、D7约20%，且有至少3人能具体说明主动回来做什么。小样本只能用于方向判断，不具统计显著性；即使达到这些比例，也不证明能规模获客/收费。反过来，严重数据安全问题不因留存不错而放行。

## 8. 第4周：依据证据选方向

| 观察结果 | 决策 |
| --- | --- |
| QQ许可满足、真实接入稳定、用户主动返聊，预算和审核可控 | 下一阶段只补QQ最小服务化；桌面保持可选，不再双线扩张 |
| 桌面常驻/养成被主动使用，资源和交互可接受，QQ需求弱 | 专注Windows可靠性、素材和独立交付，停止QQ新增投入 |

| 安全、额度、身份隔离或关键稳定性失败 | 停止受影响内测，修复/复核，不扩大人数 |

第30天交付不要求“成功创业”，要求有：完整版本基线、许可/素材结论、真实使用任务日志、每渠道人数/分母、已知缺失、成本假设与实际费用分栏、关键故障、用户价值结论，以及继续A/B或暂停的明确选择。
