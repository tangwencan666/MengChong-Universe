# P8.5 宠物领养与多实例：本地实施计划

基线为 7d8444af，保留原有 193 处未提交成果，先保存源副本与历史验收哈希。先前演示正常退出，数据保留。本轮不关机、不推送、不部署、不调用付费模型，不改共享 PostgreSQL，不改历史证据。

1. 复用 0006 的 Pet UUID、owner_id、独立 companion/chat binding 与 pet memory 复合外键，不新增共享库迁移。新增明确的实例接口，以现有 appearance_config.asset_id 解释 species_id；pet_instance_id 始终是 Pet UUID，owner_user_id 只来自认证。旧外观按 role_type 兼容并明确标识，不按名字推断身份。旧 API 不改变。
2. 新增领养/实例管理页面：五种模板可重复领养、显式自定义名字、独立幂等操作键、资料和人格编辑、召唤/收回。删除复用现有不可逆归档：实例离开活跃列表、停止生成、聊天/记忆保留，独立记忆授权仍可撤销和删除。两步确认，明确区分取消操作与已提交归档；不虚构恢复归档或物理擦除能力。
3. 在现有最多五个实例窗口上增加按账号保存的当前/上次组合。重启后重新登录才恢复，逐实例复核所有权、状态和资源边界；一键收回不会删后端记录，恢复不会唤回归档宠物。身份刷新同步名字，位置仍按 owner + instance UUID 保存。
4. 复用本地协调器，支持同种和异种独立实例；复用按需资源缓存。资源压力下停随机/移动、拒绝额外分配，保留聊天状态和收回/退出，不擅自关闭带草稿窗口、不改变用户开关。
5. 离线后端/前端/桌面回归与真实 Windows/Electron：重复领养、同种上下文/记忆/跨用户隔离、确认/取消/归档、身份不变重命名、组合/位置重启恢复、五同种资源复用、1/3/5 宠性能及五同种长测。Mock 必须明示，真实模型与其他物理设备未验证项如实保留。
6. 完成后只提交 P8.5 增量。原有未跟踪前置模块不整体夹带入提交；新增适配模块，既有受影响跟踪文件按本轮前副本分离提交。保存最终报告、性能数据、提交台账、数据库只读比较与进程端口清理结果。
