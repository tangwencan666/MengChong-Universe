## 透明度、对齐与限制

检查器只使用 Node 标准库解析 PNG、验证逐块 CRC、解压和读取像素；没有裁切、缩放、重编码、去噪或编辑图片，也没有安装图像处理依赖。

| 指标 | 睁眼 | 闭眼 |
| --- | ---: | ---: |
| alpha恰为0的像素 | 767,179（48.803%） | 766,482（48.759%） |
| 图片最外一圈最大alpha | 1／255 | 0／255 |
| 原始alpha大于0的边框像素 | 35 | 0 |
| 可见包围盒，alpha≥8／255，left/top/right/bottom | 87／27／1215／1207 | 86／26／1215／1208 |

睁眼图存在极低覆盖度的1／255噪点，所以“raw alpha>0包围盒必须完全一致、每个边框像素必须严格为0”的首次判据失败。它不是可见角色被裁断；所有非零像素统计仍原样保留。最终测试采用明确的可见覆盖阈值8／255，同时要求最外一圈最大alpha≤1／255、四边可见留白至少8像素、两帧可见包围盒各边差≤4像素；本次实测差≤1像素。没有放行可见角色触边或把白色截图背景当透明。

**两帧不是全图像素完全一致。** 以RGBA任一通道差>8计，可见变化共210,202像素，其中计划眼部区域内35,239、眼外174,963。生成式编辑会改变一些色值，因此不能直接宣称全身无漂移的逐帧动画。

运行时方案为保留睁眼图作为主体，只将闭眼图的矩形眼部区域（x=28%–64%，y=35%–51%）叠加，避免把闭眼图其他部位的生成差异带入头饰、头发、服装、鞋子与尾巴。目视该区域包含双眼，未发现明显眼位错移；真正显示效果、边缘接缝、眨眼节奏和显示缩放仍须以原生运行截图和测试判断。

当前没有可用的独立尾巴分层，也没有验证尾巴骨骼或变形动画。不把整体呼吸／移动或静态尾巴描述为“独立摇尾巴已实现”。
