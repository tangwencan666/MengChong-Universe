## 1. 目标与边界

用户可以选择让自己的 AI 记住求职方向、交流偏好、重要经历、待续话题和明确提出的事项，并随时查看、修正、撤销、删除、导出。记忆属于用户账户，不属于某个窗口、设备或付费套餐。未来网页、Windows 客户端、手机 App、桌面宠物使用同一服务端权限与数据。

P4 首版仍使用 Mock Provider；通过可观测测试证明记忆被正确选取和注入，不宣称固定 Mock 回复已经理解用户。暂不建设向量数据库、自动全历史挖掘、多智能体、客户端后台监听、支付或生产发布。

## 2. 四层数据必须区分

| 层 | 用途 | 当前事实 / P4 决策 |
| --- | --- | --- |
| 当前会话上下文 | 回答当前输入所需的本会话完整轮次 | P3 已持久化；当前最多 10 个成功历史轮次、32,000 历史字符，不等于精确 Token 限制 |
| 最近话题 | 首页继续上次聊天的入口 | P3 是真实用户消息摘录和固定问候，不是 AI 摘要；`ChatPreferences.recent_topic_enabled` 独立默认关闭 |
| 长期记忆 | 经确认的跨会话事实或偏好 | 本文设计；独立默认关闭，全局开启不代表自动保存所有对话 |
| 本次检索结果 | 一次生成使用的有限记忆子集 | 临时计算，保存引用和版本，不另存完整 Prompt 或复制一份长期记忆 |

打开最近话题不会打开长期记忆，反之亦然。删除或关闭任一层都不应悄悄改变另一层授权。记忆删除会改变未来模型上下文使用边界，但不自动删除历史聊天；界面必须解释这一点。

## 3. 用户流程

### 3.1 首次使用

记忆管理页显示“长期记忆尚未开启”。用户可以查看说明，再主动开启。说明需明确：保存哪些信息、哪些场景会使用、如何关闭及删除、数据保留边界、当前模型为 Mock。不同意不影响现有聊天。

全局开关只允许后续主动预览、确认保存和检索。不得因此扫描历史、创建画像或把“你喜欢怎样交流”等推测写成事实。聊天中的“记住这件事”文本也不直接写库，应呈现可编辑确认卡，避免模型误判授权。

### 3.2 主动保存

两种入口：记忆页手动添加；本人某条用户消息上的“记住这条”。聊天来源可以显式选择 1–5 条本人用户消息，不能把助手回答或 Mock 固定文本当作用户经历。

聊天来源流程：选择来源 → 明确请求服务端预览 → 展示候选内容、类别、有效期和来源 → 用户编辑 → 对单条点击“确认保存”。手动添加则在本地表单展示待确认值，不需要调用消息预览接口；两者在保存时都重新检查安全策略。服务端预览最多三条候选，默认不勾选，不批量默许；取消预览不产生长期记忆记录。源内容包含明显敏感信息时，预览和保存均阻止，提供不回显敏感值的原因。

候选不会在 PostgreSQL、Redis、浏览器持久存储或日志中保存。浏览器只在当前授权界面保留临时内容，五分钟过期；确认后重新验证来源、授权、版本和敏感信息。预览不等于保存，HTTP 超时不显示保存成功；重试必须复用幂等键并核对资源。

### 3.3 查看与使用

记忆页展示类别、正文、最近确认时间、到期日、状态、来源入口。被检索使用时，可以通过独立来源接口查看本次生成用过哪些记忆及版本；不会在 SSE 中广播记忆正文。

普通聊天没有相关记忆时继续回答，不强行套用。不要将用户暂时的情绪、求职困境或一次表达永久定性。记忆是用户提供的资料，可能过时，不是事实裁决或系统指令。

### 3.4 纠正、撤销、关闭、删除

| 操作 | 行为 |
| --- | --- |
| 纠正 | 展示当前值、允许编辑并重新确认；覆盖当前正文，版本递增，不维护可恢复旧正文历史 |
| 单条撤销 | 立即停止该条用于检索和模型上下文；保留正文供本人查看、导出、删除 |
| 全局关闭 | 停止预览、保存和使用；所有当前 active 条目标为 revoked，保留供本人管理；最近话题开关不变 |
| 重新开启 | 不恢复旧条目；需要逐条重新确认，过期条目同样如此 |
| 删除 | 主存储清空该条正文、标题、摘要等可读派生内容，仅留无正文墓碑/必要审计；不可恢复、不可继续注入 |
| 导出 | 即使关闭也可导出本人的非删除记忆及状态、来源元数据，不包含认证信息、第三方内容或已删除正文 |

删除、撤销、纠正或到期会使旧授权快照失效，取消相关旧快照生成。首版采用保守的账户级屏障：**未来模型不再自动加载本次隐私变更之前接受的聊天轮次**，以防旧回复转述的记忆再次注入；服务端用逻辑版本而非设备时钟判定，聊天记录仍可阅读。UI 提示“后续回复将使用新的记忆设置；此前聊天仍可查看”。用户再次主动输入相同事实属于新的当前输入，不能声称能从用户输入中“彻底抹去”该事实。

已经发给模型或客户端的数据无法召回。在途网络发送及备份的保留边界必须解释，不能把逻辑失效描述成瞬时全介质物理擦除。

## 4. 类别、内容与有效期

| category | 含义 | 新条目默认有效期 |
| --- | --- | ---: |
| `career_goal` | 求职方向、岗位目标 | 90 天 |
| `communication_preference` | 用户自己表达的交流偏好 | 180 天 |
| `experience` | 用户确认的重要经历 | 180 天 |
| `open_topic` | 用户选择保留的未完成事项 | 30 天 |
| `explicit_note` | 其他明确要求记住的普通事项 | 180 天 |

所有 active 条目必须有未来到期时间，最长 365 天；不提供“永久”默认值。到期不自动续期、不付费续命；可以重新预览并确认。用户能看见到期状态，后台处理延迟不能使过期条目继续被使用。时间统一以服务端 UTC 判定，界面按用户时区显示。

标题 1–80、正文 1–1000 个 Unicode 码点；摘要上限 240，首版为正文的确定性显示摘录，不增加事实。每用户最多 200 条非删除记忆（含撤销、过期、待重新确认），每条最多 5 个来源。配额不等于 Token 钱包余额。

密码、密钥、验证码、金融/证件号码、精确住址、第三方隐私、医疗诊断及危机心理表达不进入首版记忆候选或长期画像，手动输入同样受检查。检测并不完美，不宣称能识别所有敏感信息；上线前必须通过安全金标和人工审阅。

## 5. 来源、删除与多端

来源只包含同一账户的会话/用户消息 ID，或“本人手动输入”。详情显示真实出处，不生成不存在的经历。来源会话被逻辑删除后，其派生记忆停止使用；不能静默变成脱离来源的事实。需要独立保留时，由用户另建手动条目并再次确认。

多端以 PostgreSQL 为准，不把桌面宠物的本地缓存变为授权来源。设备从后台恢复、重连、账号切换时先拉取授权和版本再加载正文。首版不支持离线写入或持久离线记忆；本地点击关闭但网络失败时应显示“尚未同步”，不能假称服务器已关闭。

## 6. 安全与商业边界

用户不会因 Token 用完失去查看、撤销、删除、导出记忆的能力，也不会自动丢失记忆。不得用“我会忘了你”“只有充值才能继续关心你”等表达诱导付费，不制造 AI 情感依赖。

高风险心理表达走独立安全响应：简短关切、鼓励联系现实支持或当地专业帮助，不诊断、不记录危机标签、不承诺监护或保密能力。安全响应不依赖记忆开关或钱包；尚未实现并验证的风险检测不得宣称已保护用户。

## 8. 成功指标与非目标

必要指标：越权检索为 0；没有确认的长期记忆写入为 0；删除后新调用输入包含旧记忆为 0（包含已知派生历史路径）；相关性、预算和竞态通过可重复测试。用户能独立关闭最近话题与长期记忆，并清楚区分“预览”“已保存”“已撤销”“已删除”。

非目标：真实模型效果、自动诊断、自动全面总结、完美敏感信息识别、完整物理灾备擦除、生产合规认证、支付/Token 计费及公开部署。上述事项不能由文档或 Mock 测试冒充完成。
