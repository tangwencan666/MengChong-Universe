# P8.2 第二阶段：内测发行、更新及诊断设计

本阶段不发布、不推送、不连接支付，不启用真实模型。此文区分已实现的本地准备与尚未具备的发行条件。

## 当前发行事实与最小准备

现有 portable 脚本只复制并校验本机 Electron 与前端资源，不是 Windows 安装器，也没有卸载入口。原主程序将 userData 固定在安装目录下的 `.runtime/profile`，更新覆盖或卸载可能影响位置记录；本轮已改为打包运行时使用 `%APPDATA%/WeiBiYe`。开发模式与显式 `--profile-dir` 保持原语义，不迁移或删除旧配置。

统一 AppUserModelID 为 `com.weibiye.desktop`，界面/安装器名称为“未毕业”，可执行文件为 WeiBiYe.exe。新增 app.ico 使用项目原有原创几何图形重新渲染16–256px帧，不修改宠物美术资源。

安装器准备采用固定 electron-builder 26.18.0 与既有 Electron 45.2.1。构建配置为 per-user、asInvoker、无自动提权、无安装完成自动启动，卸载不删除用户数据。签名校验开关保持开启。当前只允许显式本地未签名构建，不是签名发行；没有发布端点、发布Token、签名凭据或自动更新模块。

本地构建通过既有严格白名单 portable staging，包含源依赖、当前前端产物及真实第三方许可，再由 builder 组装 NSIS；不打包测试账号、profile、数据库、API凭据、node_modules开发工具或P7本地未授权素材。只有本机下载的构建工具参与打包，不安装应用、不更改系统安全设置。

构建子进程先按名字过滤模型、签名及发布凭据；拒绝隐式读取 desktop 下的环境文件；强制 `publish: never` 与 `CSC_IDENTITY_AUTO_DISCOVERY=false`。程序签名和发布未来必须单独配置与审批，不能使用其他项目的环境凭据。

## 安全自动更新方案（尚未接通）

策略文件 `desktop/release-policy.json` 默认禁用更新、自动下载、退出安装、降级及发布。没有可信更新域名、签名证书、发布者名称或公钥时，不产生更新网络请求。

NSIS 的未来更新应使用与 NSIS 匹配的 electron-updater，不能把 Electron 原生 Squirrel/MSIX 的 autoUpdater 配置直接套用。平台与配置依据：[Electron autoUpdater](https://www.electronjs.org/docs/latest/api/auto-updater)、[electron-builder v26 自动更新](https://www.electron.build/v26/docs/features/auto-update/)。当前稳定构建工具为26.18.0，未按未发布v27文档声称能力已经存在。

拟定状态机：禁用 → 用户检查 → 单次校验清单 → 展示版本与大小 → 用户同意下载 → 完整性及发布者验证 → 等待安全退出 → 用户确认重启安装。取消检查不自动重试下载；不在用户聊天或导出过程中重启。

服务端清单包含 appId、渠道、架构、版本、最低兼容API、发行序号、有效期、大小与SHA-256，并使用独立离线签名密钥签名；客户端仅内置公钥和可信HTTPS主机，不接受渲染器提供的更新URL或任意命令。公钥轮换必须由现有信任根授权。

下载采用流式有界写入独立临时目录；先校验清单签名及有效期，再校验实际字节数/哈希、Windows Authenticode信任链与固定发布者，最后才允许安装。不能因证书、时钟或网络失败而关闭验证。哈希仅证明文件与清单一致，不能替代发行者身份。

版本必须单调前进，内部渠道不能无提示切换公开渠道；拒绝重放、过期清单、架构/appId不符及未授权降级。自动回退二进制不等于数据库降级，禁止自动迁移回退共享数据库。初次启动失败的回退需使用上一份仍可信的签名包，并保持服务端API/数据兼容。

证书与签名准备依据：[electron-builder v26签名](https://www.electron.build/v26/docs/features/code-signing/)、[v26 Windows配置](https://www.electron.build/v26/docs/win/)。当前没有完成证书配置、签名更新、断网断电恢复及升级回滚实测，不声明自动更新已上线。

## 卸载与兼容性验收

卸载只移除本安装目录、快捷方式及本应用卸载注册项；用户位置、可选诊断与服务端聊天/记忆默认保留。清空账号数据必须走独立的明确操作，不能由卸载器顺带删除。

必须在干净的标准用户Windows环境验证：安装、重装、版本升级、应用仍运行时卸载、卸载后数据保留、中文及空格路径、杀毒/SmartScreen、非管理员权限、离线后恢复。当前主机不自动安装或卸载应用，不把配置检查当成上述实测。

当前客户端仍只连接显式loopback开发API，安装器不包含Python/PostgreSQL/Redis后端。熟人独立安装体验前，必须先确定并验收托管HTTPS服务或受控随包服务；不能要求普通用户临时配置Docker/数据库，也不能为了发行放宽来源/认证/宠物隔离。

## 内测日志与崩溃诊断

已实现可选 `--local-diagnostics` 的本地白名单事件日志，默认关闭，不上传。仅记录固定schema、时间、应用版本、事件枚举、角色枚举、退出原因枚举和小范围窗口/宠物数量；不接受任意error对象、message、stack、URL、请求头、用户标识或正文。文件按256KiB旋转，最多两份。

renderer-gone/child-process-gone、主界面释放/恢复及启动/退出失败仅写固定码。模块拒绝未知字段后才读取值；不会“先记录所有内容再尝试脱敏”。IO失败不能导致宿主崩溃或绕过身份检查。

不启动Crashpad收集或上传内存转储：即使 `uploadToServer:false`，原生转储仍会保存到本机，无法保证不含聊天正文、Cookie/Token或其他内存内容。[Electron crashReporter说明](https://www.electronjs.org/docs/latest/api/crash-reporter) 明确区分本地存储与上传；本产品不能把“未上传”宣传为“未收集敏感数据”。不修改Windows全局崩溃策略。

未来用户自愿提交诊断时，先在本地重新校验每行白名单并展示预览，再由用户选择发送；不附带profile、Cookie库、SQLite、截图、netLog或minidump。用户可撤回未来诊断，不把“同意诊断”并入模型调用或记忆授权。

诊断功能只覆盖已实现的枚举事件与本地存储；主进程致命崩溃后的完整恢复、用户导出界面、远程接收服务尚未实现。
