# WeiBiYe 产品范围

更新日期：2026-11-02。当前方向：面向普通消费者的独立多宠物 AI 桌面陪伴软件。

用户与宠物自然聊天，每只宠物拥有独立人格、聊天记录和用户授权的长期记忆；宠物可从主界面进入 Windows 桌面，多只同时活动，支持拖动、点击、互动和收回。P6增加三宠Windows桌面开发预览；最终可下载安装的消费者发行版本仍需单独验收，不能把portable预览当作安装分发完成。

界面清理已保存在本地提交83c1b094；本轮增加宠物身份、人格快照、聊天与长期记忆隔离。只在全新隔离数据库验证0006，共享开发库保持0005。既有用户数据、历史验收与备份继续保留。

## 一、保留

| 模块 | 保留内容 | 当前边界 |
| --- | --- | --- |
| 账户与认证 | 注册、登录、恢复、Cookie 会话、撤销、CSRF、用户归属和角色权限 | 邮件默认本地 Mock；不是公开发布验收 |
| 聊天与会话 | 会话管理、持久化消息、SSE、取消、幂等、重放和历史恢复 | 当前模型默认 Mock；保持 `/api/v1/companion` 契约兼容 |
| 授权记忆 | 管理、候选预览、逐条确认、来源、导出、删除、撤销、检索、预算与隐私屏障 | 保留旧版账户级记忆；新宠物使用独立授权、记忆、检索和隐私屏障，需0006 |
| 宠物基础 | 独立pet_id、名称、角色、人格与外观配置、隐藏及归档 | 新生成保存人格快照并注入Mock；P6加入三宠Windows透明窗口和原创2D动画，Live2D未实现 |
| Agent Runtime | LangGraph 状态流、上下文组装、Provider 适配、模型输入屏障 | 只围绕宠物对话，不扩展通用 Agent 平台、市场或任意工具执行 |
| 安全与基础设施 | PostgreSQL、Redis、版本能力检查、日志脱敏、限流、测试和 CI | 模块化单体；不增加无关复杂基础设施 |
| 内容安全 | 高风险安全响应扩展接口、用户隐私保护及必要审计边界 | 不因移除社区而删除防护；Mock 不声称执行真实心理健康风险判断 |

保留4张账户／认证表、6张伙伴／聊天表和6张记忆表的既有职责。其余遗留实体的保留状态见下文，当前总表数不是消费者功能数。

## 二、明确移除的前端范围

| 项目 | 本轮处理 | 删除影响与保护 |
| --- | --- | --- |
| 社区广场、动态与帖子详情 | 移除 `/community`、`/posts/:id` 页面、路由和入口 | 旧深链进入通用找不到页面，不再呈现社区业务 |
| 帖子、评论、点赞等社交展示 | 移除虚构帖子列表、互动展示及社区首页推荐 | 不删除数据库里的帖子或历史用户数据 |
| 求职记录与招聘展示 | 移除 `/applications` 页面、表格示例、筛选及导航 | 不删除 `job_applications` 或修改其归属检查 |
| 求职导向快捷操作 | 替换求职建议、面试复盘等固定入口，提供日常聊天方向 | 用户仍可自然聊工作或过去经历，不过滤其私人历史内容 |
| 旧产品宣传 | 将校园、毕业季、匿名互助社区、求职平台导向改为宠物陪伴定位 | 产品名“未毕业”保留；它不限定用户年龄或职业 |
| 演示数据 | 去掉社区及求职布局 fixtures；聊天示例改为普通生活话题 | 所有留下的 Mock 内容仍明确标记，不冒充真实用户或真实模型结果 |

前端通用状态提示从社区页面移到共享组件，避免宠物、钱包或账户页面依赖已移除的社区模块。认证、聊天状态机、SSE 解析和记忆授权机制不因导航清理而重写。

后端 `community`、`applications` API 和模型暂不移除：旧迁移、模型注册、外键及权限回归仍引用它们。当前不新增相应业务；后续即使确认退役，也须先设计兼容、归档或导出方案，不能直接删表、删字段或清空数据。

## 三、待确认，暂不删除

| 项目 | 待确认问题 | 擅自删除的影响 |
| --- | --- | --- |
| 钱包与使用量账本 | 采用托管模型额度、订阅、用户自带密钥还是其他方案；消费者是否需要现有钱包页面 | `usage_records` 关联会话，已有整数账本与权限测试；不能把 Token 额度误当作宠物金币直接删除 |
| 管理后台 | 消费者界面是否保留入口，账户支持与运营能力放在哪一端 | 管理业务占位和角色机制不是同一件事，删除页面不能连带去掉 RBAC |
| 社区举报与审核遗留 | `reports`、`moderation_actions` 及后台社区审核是否退役 | 存在外键与历史审计关系，不能整包删除 moderation 或聊天安全处理 |
| 旧记忆分类与求职词法 | `career_goal` 等契约枚举、候选提取规则和旧 Prompt 的兼容方式 | 数据库 CHECK、API 和历史数据仍使用旧值；本轮只调整展示用语，不改枚举或自动改写用户记忆 |
| 公开 Mock 与访客演示工具 | 是否在消费者版本关闭或退役 `/api/v1/companion/demo/stream`、演示访客切换及手动载入虚构历史 | 基础流协议和历史隔离测试仍使用它们；可另行评审迁入开发模式，真实私人聊天与演示链路不能混淆 |
| Windows 宿主 | Electron、Tauri 或其他方案的选择与验证范围 | 影响运行时、IPC、窗口与安装分发；本轮不引入依赖或预设选型结果 |
| 提供商与密钥模式 | 托管密钥与用户自带密钥的边界、成本说明及用量入口 | 涉及安全、计费与用户体验；本轮不调用真实 GPT／DeepSeek 或新增支付 |

这些项目需要后续确认后再实施移除或替换。当前没有喂食、金币、等级、日常任务或以情感依赖推动付费的开发计划。

## 四、已建立的宠物基础与当前缺口

1. 新增宠物CRUD、隐藏／归档、受控人格／外观配置与服务端pet_id；人格快照随生成任务保存，Mock／Spy可验证实际输入。
2. 新会话、生成任务、SSE与用户＋宠物绑定，旧v1入口仅访问legacy；幂等、取消和重放不改变身份。
3. 宠物记忆使用独立授权和存储，逐条确认、来源、检索、预算与隐私屏障保留；旧账户授权及记忆不自动归属。
4. 宠物最近话题尚未实现，宠物页不读取旧版最近话题；旧授权设置保留且独立。
5. 目前没有Windows桌面宿主、透明窗口、多宠物调度、托盘、动画资源包与安装器。
6. Provider仍为Mock验证；DeepSeek与消费者密钥模式、真实模型人格效果尚未验收。共享库升级0006需另行授权。

具体实现和实际测试结果见[宠物作用域契约](PET_SCOPE_CONTRACT.md)与[本轮验收](PET_SCOPE_VERIFICATION.md)，不把占位外观或Mock回复当作桌面能力。

## 五、数据库与历史记录

保留所有已应用迁移、P3／P4 API 契约、历史验收报告和项目外备份。开发库0004→0005已于2026-11-02提交并通过原数据及只读健康核验；该轮最终写入型冒烟因任务切换尚未完成，不将其记为完整正式验收通过。

新定位不授予删表或擦除历史数据的权限。未来宠物记忆隔离应使用经审查的向前迁移，并由用户明确选择旧记忆的归属；不得把账户旧记忆默认复制或授权给每只宠物。
