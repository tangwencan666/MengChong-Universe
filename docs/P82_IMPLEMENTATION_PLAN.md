# P8.2 第一阶段：Windows 桌面宠物 MVP

基线：2026-11-02，`codex/consumer-desktop-pivot`。既有大量未提交成果全部保留；本阶段不整理或提交无关后端、前端、历史文档和验收证据。

## 代码检查与最小范围

复用 `desktop/src/main.cjs`、`manager.cjs`、`motion.cjs`、受限 preload、透明窗口和已有 SVG 宠物。聊天继续复用 React PrivateChatProvider、Cookie/CSRF、按宠物 API 与持久化 SSE。宠物渲染器没有账号凭据和网络模型能力。

现有能力：透明无边框窗口、三宠物独立身份、拖动、托盘、按宠物打开聊天、退出清理和原有安全检查。

缺口：坐标只在内存中且限制主屏；缺乏重启恢复；视觉状态仅 idle/walking/resting/dragging，未连接聊天状态；缺乏有频率限制的本地问候。

## 分阶段实现

1. 归档 P8.1 分项结果，冻结本方案；备份现有源码并记录历史证据哈希。
2. 本机位置与显示器：在 Electron userData 中仅保存按 owner+pet 哈希隔离的坐标和显示器几何；有界文件、原子替换，拖动结束或退出才写，不在每帧写盘。恢复必须先通过现有账号与宠物权限检查。Electron 统一使用 DIP，多显示器按真实工作区限制，避免落在显示器间隙；拔屏/改 DPI 后重新夹取。
3. 状态与互动：保持运动状态独立，增加 idle/happy/thinking/speaking。独立 React 展示组件订阅现有 ChatContext，仅向受限宿主发送当前聊天的 generation/session/本地展示修订号/状态元数据，不发送正文、记忆或密钥；不修改聊天业务状态机。修订号不是权威 SSE 事件序号。宿主校验窗口及宠物作用域，拒绝迟到/重复终态回退；其他宠物不受影响。问候使用本地固定文案、冷却时间及临时气泡，不创建消息、会话或模型请求。
4. 测试与验收：位置/显示器/状态机/IPC 隔离单元测试；真实 Electron 重启恢复和窗口集成；现有 AI 链路离线回归；实际 Windows HWND、拖动、桌面截图、焦点和进程清理证据与合成模型证据分别标注。

## 资源和交互约束

- 复用单一宿主调度器，不为每只宠物增加高频计时器或后台推理；默认安静停留，CSS 动画支持减少动态效果，隐藏时暂停。
- 宠物显示使用 showInactive，不周期性 focus；只有明确点击聊天或主窗口才聚焦。透明空白区域维持鼠标穿透。
- 位置记录按用户与宠物隔离；不恢复账号登录，不扩大 IPC 为任意文件、URL 或系统命令。
- 收回单只宠物只关闭窗口，不删除宠物、账号、会话或记忆。托盘明确提供退出应用。
- 不改共享数据库、容器或数据卷，不调用真实模型。实际只有一台显示器时，多显示器/DPI 只能标记为几何模拟已测，不能宣称真实多屏硬件通过。
