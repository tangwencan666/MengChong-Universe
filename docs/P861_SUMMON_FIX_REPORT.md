# P8.6.1 宠物召唤范围修复

日期：2026-11-03。最终状态：`P861_SUMMON_SCOPE_FIXED`。

## 根因和证据边界

没有发现按领养顺序截取前五只的候选集合，也没有发现用名字或数组索引代替实例 ID 的召唤路径。列表仍按现有接口分页加载，召唤仍由用户选择的 `pet_instance_id` 发起并核验所属账号。

实际可复现的缺陷是**把已注册的隐藏窗口缓存数当成桌面显示数量**：

- Electron `release()` 用 `records.size >= 5` 限制新实例；隐藏的旧窗口仍留在 records 中。
- React 用 `desktop.length` 禁用召唤按钮并显示数量；同样包含隐藏实例。
- 恢复一个含五只隐藏宠物的旧桌面组合后，屏幕实际为零只，系统却显示已占满五个名额。任何未注册的实例，包括第七只刀盾，都不能召唤。

修复前的稳定 Windows 探针在等待恢复完成、五个窗口均 hidden 后复现了该失败，新增单元回归也先失败于 `PET_LIMIT`。**真正没有任何记录的新配置在修复前即可直接召唤第七和第八只**，本报告不将其误写为原本也失败。用户仅确认从“已领养的伙伴”点击召唤，没有提供当时按钮状态或原始错误，因此没有声称读取到了用户原始失败瞬间的全部状态。

修复前探针：`.verification/p86/p861-probe-63d4b093-525c-443c-be9e-26ddc3640db4/probe.json`。

## 最小修复

1. 显示名额按 `!record.hidden` 计算，召唤及重新显示共用五只上限。已显示实例重复召唤不占新名额。
2. 显示数量不足五只时，可直接选择任意可访问的已领养实例 UUID；不删除、重排或预先召唤其他宠物。
3. 缓存已达五只时，优先释放一只隐藏且没有打开聊天窗口的闲置桌面窗口，保留它的身份、位置、行为设置及持久化关系，不调用宠物删除接口。
4. 打开的聊天及未发送草稿不因缓存置换而关闭。如果隐藏实例都有聊天，继续保留它们；原有全局 12 个窗口及内存资源保护仍生效，不能无限创建窗口。
5. 桌面组合序列化仍最多五只，优先包含所有可见实例，保留入选实例原有相对顺序。隐藏聊天缓存不能挤掉可见实例的重启恢复记录。
6. 界面分别显示可见数和隐藏数；达到五只时明确提示先隐藏或收回。隐藏不占显示名额，隐藏实例重新显示也不能绕过上限。

未修改后端产品代码、数据库模型、人格模板、聊天/记忆权限、领养列表排序及宠物删除流程。
